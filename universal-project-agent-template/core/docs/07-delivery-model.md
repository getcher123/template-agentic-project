# Delivery Model

## Delivery Principles

- GitHub Issues are the canonical task contract.
- GitHub Projects is the canonical delivery board.
- One issue maps to one branch, one worktree, and one PR.
- Codex can work only on sufficiently scoped issues.
- Delivery Planner / Backlog Architect owns decomposition, backlog shape, GitHub Issues/Projects metadata, priority, size, risk, and dependencies.

## Project Statuses

| Status | Meaning |
|---|---|
| Inbox | Not triaged |
| Ready | Scoped and ready for work |
| In Progress | Work has started |
| Review | PR is open or review is active |
| Blocked | Waiting for a decision or dependency |
| Done | Merged, closed, or intentionally completed |

## Priority

| Priority | Meaning |
|---|---|
| P0 | Urgent production or blocking issue |
| P1 | High priority |
| P2 | Normal priority |
| P3 | Low priority |

## Agent Readiness

An issue is agent-ready only when it has:

- objective;
- business or technical context;
- acceptance criteria;
- allowed scope;
- forbidden scope;
- risk level;
- validation commands.
