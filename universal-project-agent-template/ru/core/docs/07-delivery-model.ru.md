# Модель поставки

## Единая карточка работы

Issue или handoff хранит цель, источник, проверяемые критерии, разрешённый и
запрещённый scope, полный baseline/checkpoint SHA, worktree, одного write-owner,
проверки, внешние полномочия и следующий шаг. Project показывает статус этой
карточки, а не создаёт второй план.

## Уровни

- Task — одно ограниченное изменение.
- Batch — связанный пакет или несколько волн; допускается один rollup PR.
- Program — несколько связанных батчей с общими зависимостями, поверхностями
  записи или очередью merge.

Роли не требуют отдельных агентов. Один Lead может писать код как назначенный
владелец. Независимые разработчики используют разные worktree; оркестратор
ведёт общие блокировки и порядок интеграции.

Каждая волна заканчивается подходящими тестами и checkpoint. Полный локальный
прогон нужен, когда он помогает диагностике; обязательный CI остаётся финальной
проверкой. Повторное ревью неизменившегося SHA без новых данных не требуется.

Агентское ревью — доказательство для человека, а не человеческий approval.
Токен, actor и repository для внешнего действия выбираются и проверяются
в целевом проекте. Завершение фиксирует фактический результат и rollback.
