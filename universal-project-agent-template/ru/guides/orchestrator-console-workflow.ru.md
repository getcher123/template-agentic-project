# Работа Lead и Program Orchestrator

Для одной ограниченной задачи используйте одного Lead/Implementer и нужные
проверки. Субагенту передавайте конкретный независимый результат, exact SHA,
scope, режим записи, критерии и stop conditions.

Для параллельного кода создавайте отдельные worktree с одним write-owner в
каждой и назначайте владельца интеграции. Program Orchestrator нужен, когда
несколько батчей разделяют зависимости, файлы или очередь merge. Блок одной
ветки останавливает только зависящую от неё работу.

Reviewer/QA по умолчанию read-only. Finding содержит воспроизведение, нарушенный
критерий и серьёзность. После исправления проверяется новый delta и затронутая
граница; неизменившийся SHA не запускает очередной круг без новых данных.

Недоступный инструмент не разрешает ослаблять sandbox или доступы. Продолжайте
независимую разрешённую работу и фиксируйте конкретный blocker.

Перед merge Lead заполняет канонический PR template: что изменилось, реальные и
не запущенные проверки, review verdicts с SHA, риски и rollback. Обязательный
CI и человеческое решение целевого проекта сохраняются.
