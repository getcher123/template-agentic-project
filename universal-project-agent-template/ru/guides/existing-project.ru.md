# Существующий проект: адаптация

1. Запусти установщик в `--dry-run`.
2. Посмотри конфликты, особенно `README.md`, `AGENTS.md`, `Makefile`, `.github/`.
3. Установи `core` профиль без `--overwrite`.
4. Вручную объедини конфликтующие файлы.
5. Заполни terminology map по текущему состоянию кода.
6. Зафиксируй legacy terms и canonical terms.
7. Добавь issue/PR templates.
8. После первого governance PR можно подключать `recommended` или `full`.

Первый PR для существующего проекта не должен менять бизнес-логику. Он добавляет только правила, шаблоны, документацию и безопасные helper scripts.
